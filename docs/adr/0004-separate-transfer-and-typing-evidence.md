# Separate transfer, personal and typing evidence

The user authorized developing the proposed learning extensions alongside the existing Guided Learning baseline. UtterLoop keeps authored-context retrieval, Sentence Family transfer, Rehearsal Tasks, Personal Sentence practice and Fluency Pass evidence separate from Course First Pass and strict scheduled Review retention because they answer different learning questions. Return Plans reuse the ordinary Practice lifecycle and phases, so their genuine due Review occurrences remain eligible under the same strict evidence rules.

Finite authored targets use the existing answer evaluator. Test variants are excluded from instruction, and first encounters, reveal, corrections and repeat submissions remain explicit. Personal expressions require confirmation and use the shared acquisition and review rules; editing the canonical target creates a new identity. Typing stores aggregate character, editing, timing and observed physical-key counts, without raw replayable keystroke histories or claims about actual fingers. These boundaries are deliberate: a single overall mastery score would conceal what was observed.

Optional workflow state is persisted locally with optimistic revisions. Closed Studio session identities prevent late autosaves from resurrecting finished work. Full Backup version 3 carries durable personal content and separate evidence, accepts historical versions without fabricated activity, and excludes both active drafts. Reset retains personal content while clearing learning evidence; full replacement and clear operations remain atomic.

Practice has one active writer per device database. A browser-native lock releases on document teardown; a durable expiring token prevents an old writer from committing after takeover. Each successful claim also advances a local ownership epoch, which remains after lease release: an older writer stays fenced even after the newer tab closes, while the latest writer may flush its final draft on leaving. Once ownership has been used, an instance that never acquired it cannot write Practice data. Review and Vocabulary management temporarily claim ownership when needed and retain the same fence after release. Browsers without the native lock use the conservative lease and explicit takeover path. Device-local data generations invalidate every old repository instance after restore, reset or clear, including the initiating page, which must reload. Generation values, ownership epochs and ownership tokens do not travel in a backup. This trades simultaneous multi-tab editing for a clear recovery path and protection of accumulated learning records.

Studio's public document API is revisioned, but its IndexedDB representation separates the small `state` row (global revision, content revision and active checkpoint) from the durable `local` row (personal content and evidence). Checkpoint-only compare-and-swap writes do not deserialize or rewrite the full history. Validated durable arrays are immutable and cached per content revision and data generation; another connection's content write invalidates that cache. Legacy single-row documents normalize on their next write, and replacement/reset updates both rows atomically. Backups carry the joined durable document without the checkpoint. Cold reads and new evidence appends still scale with history; this deliberately avoids adding a second event-store abstraction before measurements justify one.
